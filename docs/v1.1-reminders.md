# Hemera v1.1 — Reminders (product + technical spec)

**Status:** approved scope, awaiting approval of this document before
implementation. Post-MVP stage; builds on the closed MVP (v0.1.0).

Sources: product brief §7 (calm, "no notification spam") and §10.3;
requirements §11.1; architecture §12 (notifications were an explicit MVP
non-goal, now opening deliberately).

## 1. Scope

**In:** local notifications for (a) scheduled tasks and (b) a daily habit
nudge.

**Out of v1.1:** Reset My Day (v1.2), export/backup, History UI, dark
mode, widgets, recurrence, snooze, custom notification sounds, per-habit
reminder times, any network use (brief §8; `INTERNET` stays blocked).

## 2. Decisions (D13–D19)

| # | Decision |
| --- | --- |
| D13 | **Local OS-scheduled triggers only.** No `reminder` table, no schema migration. The installed set of OS triggers is the source of truth; `syncReminders` reconciles it from tasks/habits at every mutation site and once on launch. |
| D14 | **Opt-in lives in Settings only.** No launch-time prompt, no sheet-level prompt. Two switches plus one time row; the first toggle is what triggers the OS permission request (D16). |
| D15 | **Task reminders fire at `startTime`**, on the scheduled date, for tasks that are neither completed nor archived. Default is *on* once the switch is enabled (A15). |
| D16 | **Denied permission = silent fallback + settings link.** Toggling a switch on requests permission; if refused the switch stays off, and the section shows a muted line with a working "Open system settings" link. Nothing else ever mentions it. |
| D17 | **Habit nudge = one global time of day** (Settings; default **20:00**, hour-precision native time picker) and **one combined notification** naming the habits not yet done today, silenced entirely when none are outstanding. Per D13 this cannot be an "already-done" check at fire time (that needs an unreliable background scheduler), so the exclusion is computed *at scheduling time* by rescheduling the trigger after every habit state change — accepted limitation §6.2. |
| D18 | **One quiet hint on Today**, as a caption line under the pool, dismiss-once: opening Settings → Reminders or tapping the line dismisses it forever. Setting key `reminder_hint_seen`; it is only ever shown if reminders have never been enabled. |
| D19 | **Tap opens the task sheet.** Opening a notification deep-links to `/sheet/task?id=…` (ADR-0005 already anticipated this). Tapping the habit nudge opens the Habits tab. |

## 3. Functional requirements

**FR-R1 — Settings section.** A *Reminders* group sits between *Week
starts on* and *Habits*, containing:

| Row | Control | Notes |
| --- | --- | --- |
| Task reminders | Switch | Caption: "When a scheduled task starts." |
| Habit reminders | Switch | Caption names the time; the time row is disabled (muted, with caption "Turn on habit reminders first.") while the switch is off |
| Habit reminder time | Value row → native time picker | Hour precision; default 20:00 |

- AC: With both switches off, **no notifications are scheduled and no
  permission has been requested**.
- AC: Enabling a switch when the permission is not granted requests it;
  refusal leaves the switch off and shows the D16 line, without an error
  tone or second prompt.
- AC: The settings survive app restarts (keys `reminder_tasks_enabled`,
  `reminder_habits_enabled`, `reminder_habit_time`, `reminder_hint_seen`).

**FR-R2 — Task reminder scheduling.**

- AC: Scheduling a task with a start time, while task reminders are on,
  installs exactly one notification for that task at its start time.
- AC: Rescheduling, changing duration, clearing the schedule, completing,
  un-completing, deleting and archiving all reconcile the installed
  triggers to match current data (§4.3) — no duplicates, no orphaned
  triggers.
- AC: Past-dated trigger times are never scheduled.
- AC: Following a *needs rescheduling* row's one-tap **Tomorrow**, the
  reminder follows the task to tomorrow's equivalent time.

**FR-R3 — Habit nudge.**

- AC: While habit reminders are on, exactly one daily trigger exists at
  the chosen time.
- AC: Its content is "Habits today: <names not yet done>" — **no counts,
  no "you missed", no streak language** (brief §7, D6/D7 tone rules).
- AC: If every scheduled habit is already `done`/`skipped` for today at
  the moment the trigger is (re)scheduled, no notification is installed
  for that day.
- AC: The nudge never mentions a habit that was skipped.

**FR-R4 — Tone and etiquette review.** Every notification string is
reviewed against the guilt-free rule; the only permitted wording is
factual ("Water at 20:00", "Habits today: Water, Stretch").

**FR-R5 — Offline purity.** No reminder path touches the network;
`INTERNET` remains blocked in the manifest. Reminders are local-only and
work in airplane mode.

**FR-R6 — Permission on a fresh install of v1.1.** Upgrading from v0.1.0
changes nothing until a switch is toggled (no prompt, no scheduled
triggers, hint eligible).

## 4. Technical design

### 4.1 Dependencies

- `expo-notifications@~57.0.23` (SDK 57 matched, per `bundledNativeModules`).
- No `expo-background-task` / `expo-task-manager` (only needed for a
  fire-time "is it done?" check, deliberately out of scope — D17).
- `app.json`: add the `expo-notifications` plugin and an Android channel
  `reminders` (default importance, no sound customisation); `android.
  versionCode` → 2. `INTERNET` stays in `blockedPermissions`.

### 4.2 Modules (mirroring the existing layering)

- `src/services/reminders.ts` — the only place that imports
  `expo-notifications`: permission state/request, `scheduleForTask`,
  `scheduleHabitNudge`, `cancelById`, `listScheduled`, channel setup, and
  the notification-response listener. Pure-ish, auth-gated, no store
  imports (ADR-0003 adapter pattern).
- `src/domain/reminders.ts` — **pure** and unit-tested (no `expo-*`
  imports): `taskReminderId(taskId)`, `habitNudgeId()`,
  `reminderRequestFor(task, now, dateKey)` (returns trigger date or null
  for past/completed/unscheduled), `habitNudgeBody(habits, occurrences,
  dateKey)` (names outstanding habits; `null` when nothing is
  outstanding), `nextHabitNudgeDate(time, now, weekStart)`.
- `src/stores/reminderStore.ts` — switches, habit time, permission
  status, hint-dismissed, `load()`, setters, and `syncReminders()`.
  Writes settings through the existing `settings` repository.
- `src/repositories/settings.ts` — extended with typed reminder getters
  and setters (same `settings` table, no migration).
- `app.json`-level wiring plus `app/settings.tsx` (Reminders section) and
  a caption line in `app/(tabs)/index.tsx` (D18) are the only UI changes.

### 4.3 Reconciliation rules (`syncReminders`)

Run after every mutation that can affect a reminder (task create/update/
schedule/clear/complete/uncomplete/delete; habit create/update/archive/
occurrence change; settings change; app launch).

1. Cancel every installed trigger whose id is not in the *wanted* set.
2. Schedule the wanted set, skipping anything whose trigger time is in
   the past.

Ids are deterministic (`task:<id>`, `habit-nudge`), so re-running sync is
idempotent and cheap. Cancelling by id avoids storing OS identifiers.

### 4.4 Failure behaviour

A failed schedule/cancel is a non-fatal `withWriteError`-style toast and
never blocks a task or habit write: reminders are decoration on top of
already-committed data.

## 5. Milestones

- **R1 — plumbing:** `expo-notifications`, channel, permission flows,
  Settings section, settings keys, hint (FR-R1, R6; D14, D16, D18).
- **R2 — task reminders:** domain + service + sync hooks (FR-R2; D15, D19).
- **R3 — habit nudge:** combined body, time picker, rescheduling on habit
  state (FR-R3; D17).
- **R4 — verification:** timezone change, DST, midnight rollover, reboot
  survival, airplane mode, downgrade→upgrade with existing data, tone
  review (FR-R4, R5).

DoD per milestone: `pnpm typecheck` + `pnpm lint` + `pnpm test` clean,
Android export succeeds, device-verified.

## 6. Assumptions and risks

**6.1 Assumptions**

| # | Assumption | Materiality |
| --- | --- | --- |
| A15 | Task reminders default on **when the user enables the switch**; the switch itself starts off (D14). | Reversible |
| A16 | Habit nudge default 20:00; week-start setting does not affect it. | Low |
| A17 | Notification plugin addition changes the APK's manifest permissions (`POST_NOTIFICATIONS`, `SCHEDULE_EXACT_ALARM`); `INTERNET` remains blocked. Notifications are local-only. | Medium — verify on device |

**6.2 Accepted limitations**

- A habit the user completes *after* the trigger was scheduled can still
  be named in the nudge (D17) — the alternative was a background
  scheduler that Android periodically skips, which conflicts with "no
  notification spam" more than this does.
- On Android 14+, exact alarms may require the user to allow
  "Alarms & reminders"; if denied, notifications may arrive slightly
  late. Acceptable for gentle nudges; do **not** add a permission nag.
- Recurring triggers are re-installed on launch and on relevant writes;
  an app unused for several days may miss a nudge day. No catch-up
  notification is sent.

## 7. Post-v1.1 packaging plan (recorded, not part of v1.1)

1. `eas build --profile production --platform android` → **universal AAB**
   (`android.buildType: "app-bundle"`; remove the `buildArchs` filter so
   the AAB carries every ABI; bump `versionCode`).
2. `bundletool build-apks --mode=default` → per-ABI/density/language
   APKs from that AAB (plus `--mode=universal` or a `--device-spec` for
   sideloadable singles).
3. Keep the arm64 `preview` APK as the day-to-day install; APKs meant for
   wider sharing are upload-key signed (EAS manages the keystore).
4. `INTERNET` stays blocked and reminders stay local in every artifact.
